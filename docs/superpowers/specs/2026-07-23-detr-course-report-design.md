# DETR 课程实验报告设计

## 目标

生成一份约 2000 字、适合直接提交给老师的正式课程实验报告。报告同时体现论文阅读、方法理解、实验复现和工程规范，不写成单纯的实验流水账，也不展开与本次复现无关的实现细节。

最终文件保存为：

```text
reports/DETR论文阅读与复现实验报告.md
```

配套图片统一保存在：

```text
reports/assets/
```

Markdown 只使用相对路径引用图片，确保 GitHub 页面和克隆后的本地文件均可正常显示。

## 报告结构与篇幅

### 1. 摘要（约 150 字）

概括 DETR 的核心思想、三组复现实验和主要结论。摘要不堆叠环境配置，不提前展开个人理解。

### 2. 论文方法介绍（约 600 字）

按数据流介绍：

1. CNN 主干网络提取二维图像特征；
2. 位置编码与 Transformer 编码器建立全局关系；
3. 固定数量的 object queries 经过解码器并行输出类别和边界框；
4. 将检测表述为集合预测问题；
5. 用匈牙利算法完成预测集合与真实目标的一对一匹配；
6. 用分类损失、L1 边界框损失和 GIoU 损失联合训练。

实例分割和全景分割仅作为 DETR 的扩展能力简要说明，不作为本次实验结果。

### 3. 对论文的理解（约 300 字）

重点表达：

- DETR 的关键价值不只是“使用 Transformer”，而是用集合预测统一了检测流程；
- 一对一匹配使锚框设计和 NMS 后处理不再是必要环节；
- object query 可理解为一组可学习的预测槽位，而不是固定对应某个类别或空间位置；
- 全局注意力有利于处理目标之间的关系，但原始 DETR 收敛慢，对小目标相对不利；
- 简洁的端到端形式降低了检测系统的手工设计复杂度，但计算和数据需求并未消失。

### 4. 实验过程与结果（约 750 字）

#### 4.1 官方权重评估

使用官方 DETR-R50 权重在 COCO val2017 的 5000 张图片上评估。报告 AP、AP50、AP75 以及不同尺寸目标的 AP，并与论文或官方结果比较。

#### 4.2 全量数据 20 轮训练

说明在完整 COCO train2017 上进行了 20 轮训练。以训练 loss 持续下降作为训练链路有效的证据，同时明确 20 轮不足以复现论文的最终 AP。

#### 4.3 10% 数据 100 轮训练

说明使用 seed 42 固定抽取 11829 张训练图像，在四张 RTX 4090 上训练 100 轮。报告首轮、关键轮次和最终轮次的 train loss、val loss、COCO AP，并根据完整趋势判断过拟合，避免根据单个 epoch 下结论。

### 5. 工程复现与总结（约 200 字）

说明代码保留官方 Git 历史并上传至学生 GitHub 仓库，提供 Windows 官方评估入口和 Linux 四卡训练入口；数据、权重、指标和运行清单均有校验。最后总结论文理解、实验结论和后续可改进方向。

## 图表设计

报告使用四幅核心图片：

1. **DETR 整体结构图**：使用官方仓库中的架构图；
2. **COCO 指标图**：使用本地官方权重评估生成的指标柱状图；
3. **检测可视化图**：使用 Ground Truth 与 DETR predictions 对比图；
4. **训练曲线图**：根据服务器 10% 数据 100 轮的 JSON 日志重新生成，包含 train loss、val loss 和 AP。

正文同时使用一个精简表格汇总三组实验，避免图片替代关键数字。

## 数据来源

- 论文方法：用户提供的 Carion 等人 2020 年 DETR 论文 PDF；
- 官方指标：本地 COCO val2017 评估日志与机器可读结果；
- 检测图片：本地 `eval-output` 中已经生成的可视化；
- 训练曲线：服务器 `/data/lhy` 下实际训练日志；
- 工程信息：`detr-repro` 仓库脚本、配置、提交历史和公开 GitHub 地址。

## 准确性与写作要求

- 所有实验数字必须从实际日志读取，不凭记忆补写；
- 区分论文官方结果、官方权重复现结果和自行训练结果；
- 不把 20 轮或 10% 数据实验描述成完整复现论文训练精度；
- 过拟合判断同时参考 train loss、val loss 和 AP 趋势；
- 语言采用正式课程实验报告语体，以第一人称复数或客观表述为主；
- 图片下方提供图题，并在正文中解释其含义；
- 参考文献至少包含 DETR 原论文；
- 正文约 2000 字，允许因图表说明小幅浮动。

## 验收标准

1. Markdown 文件可正常打开，所有相对图片路径有效；
2. 论文方法表述与原文一致；
3. 实验数字可追溯到实际日志；
4. loss 曲线与原始 JSON 日志一致；
5. 报告包含方法、个人理解、实验、可视化、工程复现和总结；
6. 不包含密码、私钥、服务器地址或个人敏感凭据；
7. Git 工作区中的报告与图片可以安全推送到公开仓库。
